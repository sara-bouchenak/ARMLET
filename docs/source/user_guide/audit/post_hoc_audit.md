# Post-hoc audit

Post-hoc audit can be performed using the post-hoc audit mode of **ARMLET**.

## How to run ?

It can be used by running the following command:
```bash
armlet -cn post_hoc_audit
```

```{eval-rst}

.. important::
	All Hydra guidelines explained in :ref:`Running FL experiments <federation_run>` also apply for this mode, allowing users to override the configurations directly from the command line or using a YAML experiment config file.

```

The default audit config (see the example in [Audit configuration](config_audit)) is a toy example that loads and audits the results that come from the collection of FL experiments located in `ARMLET_DIR/outputs/example/post_hoc_audit`. These results were generated by running the command ```armlet -m protocol.n_clients=2,4,6,8,10```, i.e., the default federation configuration that were run 5 times, each time with a different number of clients.

## How does it work ?

When running the post-hoc audit mode, **ARMLET** instantiates a `PostHocAuditor` object with the audit configurations and runs the `PostHocAuditor.run_audit()` function.
When initializing the `PostHocAuditor` object, **ARMLET** defines which metrics to audit and how to proceed based on the audit configs. Then, it loads and preprocesses the metrics coming from the collection of FL experiments (specified with `audit.exp_dir` config) into a dataframe.
The `PostHocAuditor.run_audit()` function will perform audit tests, and then save and print the audit results.

## How is an audit test conducted?

The `PostHocAuditor.run_audit()` function will process the dataframe containing the metric results from the FL experiments in order to run several audit tests.
The audit tests are performed separately for each FL experiment and for each metric, metric type (`perf_global`, `perf_locals`, `perf_prefit`, `perf_postfit`, `comm_costs`, or `comp_costs`), and source (general, server, clients) specified in the audit configurations.
An audit test isolates the time series of the values of a metric (over rounds), then filters and aggregates them according to the specified audit configs (see [Audit configuration](config_audit)).
It then compares the remaining values (one or more, depending of the aggregegation function) to thresholds based on an objective (above or below) and finally returns an audit status (*good*, *medium*, *bad*, or *error*).

## Post-hoc audit outputs

Once all audit tests are complete, **ARMLET** will generate and save the following outputs:
- a dataframe presenting the results of each audit test;
- a dataframe that summarizes the audit by aggregating the audit results and providing sucess rates grouped by metric categories and types.
